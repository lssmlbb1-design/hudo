# Урок 1. Telegram-бот очереди для салона, мастерской или сервиса

## Что мы построим

Создадим Telegram-бота, который умеет:

- показывать услуги;
- принимать имя клиента;
- записывать клиента в очередь;
- выдавать номер талона;
- показывать примерное положение в очереди;
- отменять запись;
- хранить данные после перезапуска;


Он помнит события, меняет состояние и не теряет очередь


## Архитектура проекта

```text
favorite/queue_bot/
├── config.py          # настройки и токен
├── data.py        # хранение в JSON-файле
├── models.py          # понятия клиента, услуги и записи
├── key.py       # кнопки Telegram
├── hand.py        # реакции на команды и нажатия
├── queue.py   # правила очереди
└── bot.py             # запуск приложения
```

### Стиль «созвездие файлов»

Каждый файл отвечает за свою орбиту:

- `datab.py` он только хранит данные;
- `queue.py` знает очередь;
- `hand.py` разговаривает с тобой
- `bot.py` только собирает и запускает бота.


## 1. Состояние пользователя

Клиент проходит несколько шагов:

```text
START
  ↓
выбор услуги
  ↓
ввод имени
  ↓
подтверждение
  ↓
клиент в очереди
```

Например, слово `Анна` после вопроса «Как вас записать?» это имя. То же слово после выбора услуги может быть просто случайным сообщением.

Для учебного проекта можно описать состояния так:

```python
class QueueState:
    CHOOSING_SERVICE = "choosing_service"
    WAITING_NAME = "waiting_name"
    CONFIRMING = "confirming"
```

## 2. Модель данных

Минимальная запись очереди:

```python
queue_entry = {
    "id": 1,
    "telegram_user_id": 123456,  #типо рандом который писали вместе
    "name": "Анна",   
    "service": "Манты",
    "status": "waiting", # ну или назови по другосу то что турк ждет когда ему все запрятят
    "created_at": "2026-07-28 17:30:00",  
}
```

Для простоты будем хранить данные в JSON-файле — это встроенный модуль Python, не требует установки, а файл можно открыть и посмотреть в любом текстовом редакторе:

```python
import json
import os

DATA_FILE = "queue_data.json"

def load_data():
    if not os.path.exists(DATA_FILE):
        return {"entries": [], "next_id": 1}
    with open(DATA_FILE, "r", encoding="utf-8") as f:
        return json.load(f)

def save_data(data):
    with open(DATA_FILE, "w", encoding="utf-8") as f:
        json.dump(data, f, ensure_ascii=False, indent=2)
```

Структура данных в файле:

```json
{
  "next_id": 1,
  "entries": [
    {
      "id": 1,
      "telegram_user_id": 123456,
      "name": "Анна",
      "service": "Манты",
      "status": "waiting",
      "created_at": "2026-07-28 17:30:00"
    }
  ]
}
```

## 3. Логика номера в очереди

Номер клиента можно определить так:

```python
def get_queue_position(entries, entry_id):
    waiting_entries = [
        entry for entry in entries
        if entry["status"] == "waiting"
    ]

    for position, entry in enumerate(waiting_entries, start=1):
        if entry["id"] == entry_id:
            return position

    return None
```

Функция возвращает позицию или `None`, если запись уже не ждёт.

## 4. Кнопки пользователя

Главное меню может выглядеть так:

```text
[Записаться в очередь]
[Моя запись]
[Отменить запись]
[Правила сервиса]
```

Кнопки лучше называть действиями. `Меню 1` звучит как дверь в подвал, а `Записаться в очередь` сразу объясняет намерение.

Пример набора действий:

```python
USER_ACTIONS = {
    "join_queue": "Записаться в очередь",
    "my_ticket": "Моя запись",
    "cancel_ticket": "Отменить запись",
    "rules": "Правила сервиса",
}
```

## 5. Сценарий записи

Сценарий должен быть дружелюбным и предсказуемым:

1. Пользователь нажимает «Записаться в очередь».
2. Бот показывает список услуг.
3. Пользователь выбирает услугу.
4. Бот просит имя.
5. Бот показывает подтверждение.
6. Пользователь нажимает «Подтвердить».
7. Бот сохраняет запись и показывает номер.

Пример финального сообщения:

```text
Готово, Анна! Вы в очереди на услугу «Стрижка».
Ваш номер: 7.
Перед вами: 3 человека.
```


### Вопрос художнице

Что должен ответить бот, если очередь пуста? Придумай сообщение без сухого «ошибка 404». Клиент не обязан знать, что произошло внутри.

## 6. Проверки и защита от странных ситуаций

Добавь проверки:

- имя не пустое;
- имя не длиннее 80 символов;
- услуга существует в списке;
- один пользователь не занимает очередь повторно;
- отменить можно только свою активную запись;


Пример проверки имени:

```python
def validate_name(name):
    clean_name = name.strip()
    return 2 <= len(clean_name) <= 80
```

> Проверки это не недоверие к пользователю. Это мягкая ограда, чтобы в поле имени не вырос целый род Жапаровых
